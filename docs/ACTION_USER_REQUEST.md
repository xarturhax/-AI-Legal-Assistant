# Пустой результат action_user_request

Аудит выполнен по локальному pinned upstream `903e0c1`. После запуска стека
повторная проверка подтвердила XFAIL на настоящей KB. Для `concept_rental_housing_belarus`
агент завершился с нулём результатов при наличии определения, пяти plural-связей
статей и двух plural-связей понятий. Singular-связей статей и понятий в обоих
проверенных направлениях нет. Свидетельство находится в `evidence/iteration-live-tests.xml`.

В `user_request_agent.cpp` обе функции построения шаблона требуют одновременно
русское название, членство в `belarus_legal_term`, связанное понятие класса
`NodeVarClass`, связанную статью и структуру определения с русским текстом.
Отсутствие любой части обнуляет весь результат. Для определения понятия эти
дополнительные связи могут отсутствовать.

Основной код вызывает `generateCommonReversedTemplate`. При пустом результате он
повторно дописывает в тот же объект тот же reversed-шаблон. Direct-шаблон нигде
не вызывается. В результат добавляются определение, связанное понятие и статья,
а найденный `_main_node` туда вообще не включается.

В SCS для `concept_rental_housing_belarus` связанные понятия записаны через
`nrel_related_concepts`. C++ требует единственное число `nrel_related_concept`.
Несовпадение подтверждено и в текущем runtime-графе. Обязательный шаблон C++
не может совпасть при отсутствии требуемых singular-связей.

Условие `linkAddrs1.size() > 1` некорректно для поиска одного title-link, однако
само действие создаёт ещё один link с запросом. Исторический probe показывал
прохождение этого условия. Замена только на `!linkAddrs1.empty()` не устраняет
остальные ограничения шаблона.

## Предлагаемое исправление upstream

1. Проверять чтение аргумента и непустое содержимое запроса.
2. По каждому найденному link искать базовый шаблон названия и класса юридического
   термина с `lang_ru`. Добавлять сам `_main_node` в результат.
3. Определение и каждую связанную статью/понятие читать отдельными необязательными
   шаблонами. Поддержать singular/plural и оба направления связанного понятия.
   Создавать новый объект шаблона для каждого поиска.
4. Сохранить найденные исходным агентом результаты вместе с прямым понятием.
   Не связывать успех поиска понятия с наличием всех необязательных соседей.

Это предложение для изменения C++-агента. Исходный агент в этой итерации сохранён.
Приложение уже читает прямые понятия и связи через Python/SC-шаблоны, показывая
`agent_no_sources` при пустом результате исходного действия.

## Регрессионные проверки

`test_existing_agent_single_title_link` сохраняет XFAIL при завершённом пустом
действии. Probe теперь выводит для каждого точного понятия число определений,
singular/plural связей и направление singular-связи понятия.
`test_action_search_uses_real_sources_with_explicit_fallback` проверяет реальную
выдачу и видимый fallback. Изолированный `test_ostis_fallback.py` проверяет
непригодные узлы агента и пустой результат с дальнейшим чтением прямого понятия.

Перед применением C++-исправления нужны сборка и отдельные live-проверки
одного title-link, определения без соседей, plural-связей, обоих направлений,
неизвестного термина и сохранения старой выдачи. До этого XFAIL остаётся открытым.
