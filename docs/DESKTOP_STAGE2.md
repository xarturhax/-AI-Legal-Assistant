# Этап 2: единый desktop-интерфейс

Пользователь одобрил концепцию этапа 1 и разрешил перенести её на все страницы.
Новое ограничение: мобильной версии не будет. Оно имеет приоритет над общими
рекомендациями навыка frontend-design о mobile adaptation.

Дизайн-система сохраняется: зелёный #192b28, камень #e1e4d8, патина #b3b79f,
светлый лист #f7f8f0, чернила #263c35; локальные Prata и Golos Text.

Композиция до реализации:

```text
единая desktop-навигация / поиск / справочник / остальные разделы / кабинет
тёмная область: заголовок раздела и краткое назначение
светлая область: данные и действия
  справочник → реестр источников
  источник   → текст до 76ch + связи и закладка
  кабинет    → внутреннее оглавление, рабочие секции
  календарь  → журнал событий | форма
  документ   → просмотр бланка | поля
  форум      → фильтры, список, открытое обсуждение
  тест       → вопрос, варианты, результат
```

Главная сохраняет одобренную скульптурную композицию. Статуя не размножается по
каждому разделу. Убраны произвольная нумерация, бордовые акценты и старое оглавление.
Сетка и текст выровнены влево; данные не превращаются в ряд одинаковых карточек.

Desktop: минимальная ширина 1180 px; проверяемые размеры 1280, 1600, 1920 px.
Узкое окно сохраняет desktop-компоновку. Удаляются мобильные media queries,
кнопка мобильного меню и JS-переключение мобильной навигации. Исторические снимки
mobile из этапа 1 сохраняются как свидетельства прошлой итерации.

Python, endpoints, методы, модели, CSRF и источники данных не изменяются.
Снимок шаблонов/стилей и хеши Python/инфраструктуры сохранены перед началом
в .cache/desktop-stage2-before/.

## Итог: DONE

Все разделы перенесены в одобренную систему: главная, юридический поиск,
справочник, источники, профиль/настройки/заметки/закладки/история, календарь,
документы и заполнение бланка, форум и ответы, рекомендации, новости,
учебные тесты, вход/регистрация/восстановление/подтверждение и ошибки.

Общая оболочка теперь находится в base.html. concept_base.html и search_legacy.html
сохранены как короткие совместимые наследники актуальных шаблонов. App.css содержит
стили рабочих разделов, concept.css — палитру, типографику, главную и поиск.
Favicon приведён к зелёной палитре. Никаких внешних runtime CDN не добавлено.

Мобильные варианты удалены из действующих шаблонов, CSS и JS. Нет кнопки hamburger,
переключения matchMedia и однотипной mobile-перестройки. Единственный max-width media
query ограничен диапазоном desktop 1180–1300 px; для широкого desktop есть min-width
1800 px. Сохранены prefers-reduced-motion и печатная версия.

Визуально оценены снимки кабинета, каталога, авторизации, форума, календаря и источника.
Связанные материалы источника после просмотра перенесены из длинной боковой колонки
под текст в две колонки: короткое определение больше не оставляет большой пустой лист.
Для самого текста и служебной информации оставлены разные уровни типографики.

## Ограничения

- 15 live pytest-тестов в общем прогоне были SKIPPED без флагов запуска;
  выбранные реальные UI-сценарии проверены отдельно через Edge.
- Firefox, Safari и экранный диктор не проверялись. Мобильная версия исключена
  по новому требованию пользователя.
- У одной проверенной связанной статьи OSTIS возвращает в source.text путь
  `/tmp/.../by_act_hk1200428_article_1.html`, а не декодированный текст статьи.
  Исходный backend сохранён: UI отображает полученное значение. Проверка этой
  страницы подтверждает отображение содержимого и меру чтения, а не получение
  полного нормативного текста. Это не регрессия редизайна и не LIVE PASS чтения
  полного текста этой статьи. Искусственный текст не подставлялся.
- Осталось прежнее DeprecationWarning sc_client. Полная оценка качества LLM S6
  не повторялась, интеграции и модель не менялись.
