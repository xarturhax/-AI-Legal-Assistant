# Решения

- D001, S0: подключать ostis-legislation по точному SHA, сохранять все исходники и агентов.
  Не переносить sc-legislation-app без лицензии. Новые Python и шаблоны пишутся самостоятельно.
- D002, S0: юридические данные только из живого OSTIS, SQLite только для функций сайта.
  Аудиторский JSON не используется во время поиска.
- D003, S0: сначала action_user_request, затем явно помеченный SC-template search при пустом результате.
  Учитывать единственное и множественное написание связей. Не утверждать эквивалентность выводу агента.
- D004, S0: SDK 0.4.0 имеет глобальную сессию и неограниченное ожидание. Изолировать его в процессе
  с ограничением времени, сериализовать операции, не повторять автоматически действия записи.
- D005, S0: отсутствие Docker/WSL и локальной модели блокирует live-приёмку, но не разработку
  пользовательских функций, схем, проверок и документации.
- D006, S3: LLM возвращает только интерпретацию. Итог — детерминированная сборка выдержек,
  без нейросетевого перефразирования нормативных текстов. Факты не участвуют в SC-запросе.
- D007, S4: свои аккаунты и транзакционные функции реализованы на SQLite с Alembic,
  foreign_keys=ON и контролем владельца. Это не перенос/удаление старых SC-агентов и данных.
- D008, S5: вопросы читаются SC-шаблонами по обеим схемам singular/plural. Проверка —
  сравнение с concept_correct_answer, как в просмотренном C++ CheckTheAnswerAgent.
  Неполные/неоднозначные вопросы не предлагаются; нормативная истинность разметки не заявляется.
- D009, S5: исходные карточки документов не содержат файлов. Реализован каталог и заполнение
  подключённых txt-бланков с источником/лицензией; контентная приёмка остаётся заблокирована.
- D010, S7: после дополнительной сверки recommendation.py/topic_tags.py старого сайта
  добавлены сценарии рекомендаций, тематических меток и обратной связи. Новый лексический
  алгоритм написан независимо, использует только свой профиль просмотров и не отправляет тексты наружу.
- D011, исправление launcher: сохранять журналы вне Git и показывать этап/код ошибки;
  предупреждать о неподготовленных образах и занятом порте до Compose up. Обычный stderr
  Git/Docker не считать ошибкой без ненулевого exit code. Собственный демо-сервер на 5000
  остановлен перед пользовательским Docker-запуском; неизвестные процессы не завершаются.
- D012, launcher: хранить все .bat с CRLF и проверять рабочие файлы до запуска,
  поскольку одной .gitattributes недостаточно для уже созданных LF-файлов.
  Исправление проверяется прямым cmd.exe-запуском, а не только тестом PowerShell-функций.
- D013, S1: после подтверждённого TLS-сбоя conan.ostis.net использовать официальный
  CPack SDK sc-machine 0.10.0 через CMAKE_PREFIX_PATH. Этот путь документирован upstream;
  версия движка и исходники всех агентов сохраняются. Не менять TLS-проверки и не заменять
  юридический агент Python-заглушкой. Новый image проходит проверку dynamic libraries и версии,
  а live KB/WS проверяются отдельно после настоящей сборки.
- D014, очистка диска: удалять только подтверждённые временные кеши; для Docker —
  builder prune, для pip — cache purge. Сохранять образы, контейнеры, модели, тома KB,
  исходники и .env. VHDX не удалять и не сжимать автоматически. Проверять абсолютные
  границы и reparse points перед рекурсивным удалением кешей workspace.
- D015, S1: GWFTranslator создаёт `.generated.scs` рядом с исходным GWF. Для сборки
  использовать временную записываемую копию upstream, сохраняя оригинальный bind mount read-only
  и реальные sc-builder/sc-machine. После незавершённой установки повторная сборка непустой KB
  допускается только после остановки app/machine, создания и проверки резервного tar-архива.
  Ошибка копирования или проверки блокирует сборку; ошибка сборки не создаёт маркер готовности.
- D016, S1/S4: пути приложения вычислять от каталога пакета с учётом checkout backend/app
  и Docker /app/app; настройки окружения приоритетны. Проверять настоящий CLI миграций
  при сборке образа после USER legal на отдельной SQLite в памяти со случайным секретом.
  Постоянная SQLite мигрируется отдельно при setup; существующие пользовательские данные
  не используются для проверки образа и не удаляются.
- D017, S2/S3/S6: статус finished исходного action_user_request не считать доказательством
  наличия источников. Отражать число SC-узлов/пригодных источников и переход к шаблонам.
  Подтверждённый пустой ответ исходного агента отмечать XFAIL с причиной, сохраняя отдельную
  обязательную live-проверку fallback. Диагностика одного совпадения считает title-ссылки,
  а не накопившиеся входные ссылки прошлых действий. C++ upstream не изменяется.
- D018, тесты Windows: отдельный TemporaryDirectory на каждый запуск pytest, временный
  instance_path для fixture-приложения, без общего pytest-of-user и постоянного pytest-кеша.
  Не менять ACL пользовательских каталогов и не удалять чужие временные файлы.
- D019, S3: локальная модель подбирает названия только из словаря, прочитанного из живой
  SC-памяти, с enum в JSON Schema и повторной проверкой Python. Не добавлять статический
  список юридических терминов из датасета в runtime. Качество и задержку сравнивать
  отдельно от факта успешного выполнения запроса; пустой ответ не считается правильным
  только потому, что HTTP/SDK не вернул ошибку.
- D020, S3: доступ NVIDIA для Ollama задаётся дополнительным compose.gpu.yml.
  Локальный COMPOSE_FILE включает его при обычном start.bat. Образ и том модели
  используются из основного Compose. Ускорение подтверждается после запроса по
  PROCESSOR в ollama ps или size_vram в /api/ps.
- D021, S2/S3: использовать общую нормализацию названий для словаря OSTIS и ответа модели.
  Запятые и скобки сохраняются. Для явно указанного названия из словаря передавать модели
  это название как единственный кандидат. Точное совпадение SC-шаблона ранжировать
  перед связанными источниками исходного агента.
- D022, S5: перемешивать варианты по идентификаторам раунда и вопроса после чтения из OSTIS.
  Начальная сортировка по ID сохраняет воспроизводимость при изменении порядка чтения KB.
  Оценка ответа опирается на ID и исходный признак правильного варианта в OSTIS.
- D023, S5: каталог содержит самостоятельные заполняемые TXT-шаблоны на основе
  опубликованных образцов и требований НАРБ. Для доступа к оригиналам карточки
  ссылаются на страницы учреждения. Исходные файлы архива хранятся на его сайте.
- D024, S5: прекращать чтение RSS после первых 100 завершённых записей. Ограничить
  буфер 8 МБ и использовать полностью прочитанные записи при достижении лимита.
  Отказ без пригодных записей сохраняет предыдущий кеш и сообщает причину в CLI.
- D025, S7: проверять первичную установку в отдельной локальной копии с собственными
  портами, томами и метками образов приложения и OSTIS. Запуск использует базовую
  конфигурацию Compose на CPU и отдельный том модели Ollama.
- D026, S3: связывать процитированные entities и явно присутствующие facts с текущим
  словарём OSTIS. Поиск дополнить этими кандидатами, вернуть привязки к источникам,
  а missing_information показывать как вопросы модели. Индивидуальный правовой вывод
  не выполняется. Для неподтверждённых обстоятельств привязка отсутствует.
- D027, S2/S6: сохранить исходный агент и его XFAIL, расширить probe диагностикой
  singular/plural связей. Предложение C++-исправления зафиксировать отдельно до сборки
  и проверки на живой KB. Оценку baseline проводить и при недоступном Ollama.
- D028, S3/S6: перед поиском проверять предметные слова исходного запроса, наличие
  названий из текущей KB и grounding фактов. Общие просьбы о помощи требуют уточнения
  и не инициируют поиск по предложенным моделью терминам. needs_clarification и
  missing_information сохраняют вопросы при частичном поиске по известному предмету.
  Для запроса определения не требовать описания жизненной ситуации.
