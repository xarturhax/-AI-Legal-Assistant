# Инструкции Codex для репозитория legal-ai-assistant

Основное ТЗ: [IMPLEMENTATION_SPEC.md](IMPLEMENTATION_SPEC.md). Сначала прочитай его полностью.

## Задача
Создай единую рабочую систему: Python-сайт с прежней пользовательской функциональностью, **реальный OSTIS/sc-machine** и локальную LLM для русскоязычных юридических запросов. Windows + Docker Desktop + WSL2, один запуск после первичной установки, никаких платных API.

## Правила разработки
- Работай по этапам `S0–S7` из ТЗ. Начни с аудита оригинальных репозиториев и подготовки `docs/REPO_AUDIT.md`.
- Не переписывай движок `sc-machine` на Python. Вся **новая прикладная логика** на Python 3.11; OSTIS продолжает работать как отдельная служба.
- Не пытайся реализовать всё поверх SQLite: юридические сущности и связи должны реально извлекаться из OSTIS.
- Не используй фейковые SC-ID, юридические статьи или произвольный ответ LLM при отсутствующем OSTIS.
- Не копируй исходники `SharkoStepan/sc-legislation-app` в публичный проект, пока не установлено право на повторное использование; первоначально реализуй функциональную эквивалентность.
- Выполняй регулярные тесты; ясно различай `mock`, `live`, `SKIPPED` и `FAIL`.
- Не удаляй старые агенты, данные и тома до проверки и резервного копирования. Никогда не делай `docker compose down -v` в обычных скриптах.
- Поддерживай `docs/STATUS.md` и `docs/DECISIONS.md`, фиксируй изменения и блокировки.
- Если отсутствие Docker, сети или GPU блокирует проверку — реализуй то, что возможно, и честно отметь блокировку. Не выдавай непроверенное за работающее.
- Никогда не пушь на GitHub без явного разрешения пользователя.
